# Лабораторная работа №4. Session. Bootstrap

Вариант 3 — новостной сайт.

Работа является продолжением лабораторной работы №2. Существующие страницы, изображения, стили и файл новостей были сохранены. В проект добавлены регистрация, авторизация, PHP-сессии, AJAX и Bootstrap.

## Цель и задачи

Цель работы — получить навык разработки сайтов с использованием PHP.

В соответствии с методичкой необходимо:

- хранить сведения о текущем пользователе в сессии;
- реализовать регистрацию и авторизацию;
- хранить пользователей в отдельном файле;
- закрыть содержимое сайта от неавторизованных пользователей;
- загружать и передавать данные с помощью AJAX;
- вывести данные из отдельного файла в Bootstrap-таблице;
- добавлять новые данные с сохранением в файл;
- выполнять валидацию на стороне клиента без дополнительных библиотек.

## Регистрация

Страница `register.php` содержит форму с логином, паролем и повтором пароля. Форма имеет идентификатор:

```html
<form id="register-form">
```

Файл `js/auth.js` получает форму и обрабатывает событие `submit`:

```js
registerForm.addEventListener("submit", async function (event) {
    event.preventDefault();
```

`preventDefault()` отменяет обычную отправку формы, поэтому страница не перезагружается. Затем JavaScript получает значения полей и выполняет клиентскую проверку:

```js
if (login == "" || password == "" || passwordRepeat == "") {
    message.textContent = "Заполните все поля";
    return;
}

if (password != passwordRepeat) {
    message.textContent = "Пароли не совпадают";
    return;
}
```

После успешной проверки данные передаются обработчику `api/register.php`:

```js
const response = await fetch("api/register.php", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({ login: login, password: password })
});
```

`JSON.stringify()` преобразует JavaScript-объект в JSON-строку. PHP получает её из специального потока `php://input`:

```php
$data = json_decode(file_get_contents("php://input"), true);
$login = $data["login"];
$password = $data["password"];
```

Обработчик читает `users.json`, перебирает пользователей и проверяет уникальность логина. Если логин уже существует, возвращается сообщение об ошибке. Иначе новая запись добавляется в массив и сохраняется функциями `fopen()`, `fwrite()` и `fclose()`.

Файл пользователей имеет следующую структуру:

```json
[
    {
        "login": "user",
        "password": "123"
    }
]
```

В учебной работе пароль хранится в исходном виде, поскольку хеширование не входит в задание. В реальном приложении пароль необходимо сохранять только в виде хеша.

## Авторизация и сессия

Форма в `login.php` также передаёт логин и пароль с помощью `fetch()`. Обработчик `api/login.php` читает `users.json` и ищет совпадающую запись:

```php
foreach ($users as $user) {
    if ($user["login"] == $login && $user["password"] == $password) {
        $_SESSION["user"] = $login;
```

Перед работой с `$_SESSION` вызывается:

```php
session_start();
```

PHP создаёт новую сессию или восстанавливает существующую. Идентификатор сессии хранится браузером в cookie, а данные `$_SESSION` находятся на сервере.

После успешного входа JavaScript переводит пользователя на главную страницу:

```js
window.location.href = "index.php";
```

## Ограничение доступа

В начале каждой содержательной страницы подключается `auth_check.php`:

```php
<?php require_once "auth_check.php"; ?>
```

Проверка устроена следующим образом:

```php
session_start();

if (!isset($_SESSION["user"])) {
    header("Location: login.php");
    exit;
}
```

Если логин отсутствует в сессии, PHP отправляет браузеру заголовок перенаправления. `exit` прекращает выполнение, поэтому закрытое содержимое не выводится.

Проверка подключена к `index.php`, `adding_news.php`, `economics.php` и `culture.php`. Последние две страницы были переименованы из HTML в PHP, поскольку обычный HTML не может выполнить серверную проверку сессии.

## Выход

Ссылка «Выйти» ведёт на `logout.php`:

```php
session_start();
session_destroy();

header("Location: login.php");
exit;
```

`session_destroy()` уничтожает данные текущей сессии. После этого пользователь возвращается на страницу авторизации.

## AJAX-загрузка новостей

В `index.php` находится таблица с пустым телом:

```html
<table class="table table-bordered table-striped">
    <thead>
        <tr>
            <th>Новость</th>
            <th>Категория</th>
            <th>Дата</th>
        </tr>
    </thead>
    <tbody id="news-table-body"></tbody>
</table>
```

После загрузки страницы функция `loadNews()` отправляет запрос:

```js
const response = await fetch("api/get_news.php");
const news = await response.json();
```

`api/get_news.php` проверяет сессию, читает `news.json` и возвращает его содержимое. JavaScript перебирает массив и создаёт элементы таблицы:

```js
for (const item of news) {
    const row = document.createElement("tr");
    const titleCell = document.createElement("td");

    titleCell.textContent = item.title;
    row.append(titleCell);
    tableBody.append(row);
}
```

В полном коде аналогично создаются ячейки категории и даты. Страница полностью не перезагружается — изменяется только DOM таблицы.

Если сессия отсутствует, API возвращает HTTP-код `401`, а JavaScript переводит пользователя на страницу входа.

## AJAX-добавление новости

Форма в `adding_news.php` содержит название, категорию и дату. `js/news.js` отменяет обычную отправку, проверяет заполнение и передаёт JSON:

```js
const response = await fetch("api/add_news.php", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        title: title,
        category: category,
        date: date
    })
});
```

`api/add_news.php` проверяет сессию, создаёт ассоциативный массив новости и добавляет его к прочитанным данным:

```php
$newItem = [
    "title" => $data["title"],
    "category" => $data["category"],
    "date" => $data["date"]
];

$news[] = $newItem;
```

Весь обновлённый массив преобразуется обратно в JSON и сохраняется:

```php
fwrite(
    $fd,
    json_encode($news, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT)
);
```

После успешной записи PHP возвращает сообщение «Новость добавлена». JavaScript показывает его на странице и очищает форму.

## Полный порядок работы сайта

1. Пользователь открывает `register.php` и регистрируется.
2. JavaScript проверяет форму и передаёт данные через AJAX.
3. PHP сохраняет пользователя в `users.json`.
4. Пользователь открывает `login.php` и вводит те же данные.
5. После успешной проверки PHP записывает логин в сессию.
6. Пользователь получает доступ к закрытым страницам.
7. Главная страница загружает новости из `news.json` через AJAX.
8. Пользователь заполняет форму добавления новости.
9. AJAX-обработчик сохраняет запись в `news.json`.
10. Новость появляется в таблице после перехода на главную страницу.
11. При выходе данные сессии уничтожаются.

## Важные моменты к защите

- HTTP сам по себе не хранит состояние между запросами; сессия связывает запросы одного пользователя.
- Браузер хранит идентификатор сессии в cookie, а данные `$_SESSION` хранятся на сервере.
- `session_start()` необходимо вызвать до вывода HTML.
- `session_destroy()` удаляет данные текущей сессии.
- AJAX позволяет получать и отправлять данные без полной перезагрузки страницы.
- `fetch()` возвращает Promise, поэтому в коде используются `async` и `await`.
- `php://input` содержит тело JSON-запроса.
- `json_decode(..., true)` преобразует JSON в ассоциативный PHP-массив.
- `json_encode()` выполняет обратное преобразование.
- клиентская валидация реализована обычным JavaScript без библиотек;
- строки AJAX-таблицы отсутствуют в исходном HTML и создаются через DOM;
- Bootstrap подключён готовым CSS-файлом, а оформление таблицы задаётся классами.

## Лабораторная работа №2. Использование PHP

Папка: [`lab2`](./lab2/)

### Цель

Получить навык разработки сайтов с использованием языка программирования PHP.

### Основные требования

- разработать сайт по теме варианта 3 — новостной сайт;
- стилизовать сайт с помощью CSS; разрешено использовать Bootstrap;
- вывести таблицу с информацией, которая хранится на сервере в отдельном текстовом, XML- или JSON-файле;
- реализовать добавление новых данных и их сохранение в файл.

### Что реализовано

За основу взят статический новостной сайт из первой лабораторной работы. Он дополнен динамическими страницами и работой с файлом:

- [`index.php`](./lab2/index.php) — главная страница, которая читает новости из JSON и выводит их в таблице «Новости пользователей»;
- [`adding_news.php`](./lab2/adding_news.php) — страница с формой добавления новости и PHP-обработчиком;
- [`news.json`](./lab2/news.json) — файл, в котором хранятся названия, категории и даты новостей;
- [`economics.html`](./lab2/economics.html) и [`culture.html`](./lab2/culture.html) — сохранённые тематические страницы первой работы;
- [`style.css`](./lab2/style.css) — общий файл оформления;
- `c.webp` — баннер страницы добавления новости.

В навигации доступны четыре раздела: главная страница, экономика, культура и добавление новости. Таблица пользовательских новостей расположена в конце главной страницы, поскольку количество записей может увеличиваться.

### Как работает главная страница

В начале `index.php` функция `file_get_contents()` читает всё содержимое `news.json` в строку:

```php
$str = file_get_contents("news.json")
    or die("Не удалось прочитать файл с новостями");
```

Если файл прочитать невозможно, `die()` выводит сообщение и прекращает выполнение PHP-скрипта. Затем функция `json_decode()` преобразует JSON-строку в PHP-массив:

```php
$news = json_decode($str, true);
```

Значение `true` означает, что элементы JSON преобразуются в ассоциативные PHP-массивы. После этого цикл `foreach` перебирает все новости и формирует строки HTML-таблицы:

```php
<?php foreach ($news as $item): ?>
    <tr>
        <td><?php echo $item["title"]; ?></td>
        <td><?php echo $item["category"]; ?></td>
        <td><?php echo $item["date"]; ?></td>
    </tr>
<?php endforeach; ?>
```

### Как работает добавление новости

Форма на странице `adding_news.php` отправляет данные методом `POST` на эту же страницу:

```html
<form method="post" action="adding_news.php">
```

У полей заданы имена `title`, `category` и `date`. По этим именам PHP получает значения из массива `$_POST`:

```php
$title = $_POST["title"];
$category = $_POST["category"];
$date = $_POST["date"];
```

Условие с `$_SERVER["REQUEST_METHOD"]` не позволяет выполнять код добавления при обычном открытии страницы:

```php
if ($_SERVER["REQUEST_METHOD"] == "POST")
```

Новая запись создаётся как ассоциативный массив и добавляется в конец массива новостей:

```php
$newItem = [
    "title" => $title,
    "category" => $category,
    "date" => $date
];

$news[] = $newItem;
```

Файл открывается в режиме `w`, то есть его прежнее содержимое заменяется новым. Старые новости не теряются: перед записью они были прочитаны в `$news`, а новая запись была добавлена к этому массиву.

```php
$fd = fopen("news.json", "w")
    or die("Не удалось открыть файл для записи");
```

Массив преобразуется обратно в JSON и записывается в файл:

```php
fwrite(
    $fd,
    json_encode($news, JSON_UNESCAPED_UNICODE | JSON_PRETTY_PRINT)
);
fclose($fd);
```

- `json_encode()` преобразует PHP-массив в JSON;
- `JSON_UNESCAPED_UNICODE` оставляет русские буквы читаемыми;
- `JSON_PRETTY_PRINT` добавляет отступы и переносы строк;
- `fwrite()` записывает строку в открытый файл;
- `fclose()` закрывает файл после записи.

### Поля формы

- `input type="text"` — поле ввода названия новости;
- `select` и вложенные `option` — выпадающий список категорий;
- `input type="date"` — выбор даты;
- `required` — браузер не отправляет форму, пока обязательное поле не заполнено;
- `input type="submit"` — кнопка отправки формы.

Проверка значений в PHP дополнительно не позволяет записать пустую новость, даже если клиентскую проверку `required` обойдут.

### Полный порядок выполнения запроса

1. Пользователь открывает `adding_news.php` через веб-сервер.
2. PHP читает существующие новости из `news.json`.
3. Пользователь заполняет форму и нажимает кнопку добавления.
4. Браузер отправляет поля серверу методом `POST`.
5. PHP получает значения из `$_POST` и создаёт новую запись.
6. Запись добавляется в массив существующих новостей.
7. Весь обновлённый массив сохраняется в `news.json`.
8. При открытии или обновлении `index.php` данные заново читаются из файла и появляются в таблице.

### Что использовано сверх примеров методички

Основной код опирается на темы из методички: PHP-вставки, переменные, массивы, `foreach`, формы, `$_POST`, `$_SERVER`, `fopen()`, `fwrite()`, `fclose()`, `file_get_contents()` и `die()`.

В методичке разрешён формат JSON, но подробно не показаны следующие используемые средства:

- `json_decode()` — преобразование JSON в PHP-массив;
- `json_encode()` — обратное преобразование массива в JSON;
- `JSON_UNESCAPED_UNICODE` и `JSON_PRETTY_PRINT` — параметры оформления JSON;
- `required` — встроенная браузерная проверка заполнения формы.

Все эти средства входят в стандартные возможности PHP или HTML, сторонние библиотеки и фреймворки в работе не применялись.

### Важные нюансы к защите

- PHP выполняется на сервере, а браузер получает уже сформированный HTML.
- Страницу PHP нужно открывать через `http://localhost/...`, а не как локальный файл двойным щелчком.
- Все посетители сайта работают с одним файлом `news.json`. Авторизации нет, поэтому при публикации сайта добавить новость сможет любой посетитель страницы формы.
- Сервер должен иметь право записи в `news.json`, иначе `fopen()` не сможет открыть его в режиме `w`.
- Режим `w` очищает файл перед записью, но код сначала сохраняет старые данные в массиве и записывает обратно уже полный обновлённый массив.
- После отправки формы повторное обновление страницы может повторно отправить данные и создать дубликат. Для простой лабораторной перенаправление после POST не реализовано.
- Данные выводятся напрямую через `echo`. Для общедоступного сайта пользовательский текст следовало бы обрабатывать функцией `htmlspecialchars()`, но в этой локальной учебной работе она не используется для упрощения кода.
- Если вручную нарушить структуру `news.json`, `json_decode()` не сможет получить корректный массив. Поэтому в JSON важны кавычки, запятые и квадратные скобки.
- `die()` в этой работе используется как простая обработка ошибки: выводит сообщение и прекращает выполнение скрипта. Это не полноценная конструкция исключений `try/catch`.
- Таблица на главной формируется динамически: её строки отсутствуют в HTML в готовом виде и создаются циклом `foreach` при каждом запросе страницы.

### Цель

Получить навык разработки с использованием языка программирования JavaScript.

### Основные требования

Разработать JavaScript-сценарий, реализующий действие на странице в браузере согласно варианту, и подключить его к HTML-странице.

Для варианта №3 требуется разработать браузерную игру **«Змейка»**.

### Что реализовано

Создана браузерная игра на HTML, CSS и JavaScript:

- [`index.html`](./lab3/index.html) — заголовок, текущий счёт, рекорд, Canvas, сообщение об окончании игры и кнопка запуска;
- [`style.css`](./lab3/style.css) — тёмно-синее оформление страницы, центрирование игрового поля, кнопки и сообщений;
- [`script.js`](./lab3/script.js) — отрисовка, движение, управление и вся игровая логика;
- [`README.md`](./lab3/README.md) — подробное описание всех этапов разработки;
- [`Афанасьева_ЮР_ИУК4-43Б_2026_ЛР3_КРПО.docx`](./lab3/Афанасьева_ЮР_ИУК4-43Б_2026_ЛР3_КРПО.docx) — отчёт по лабораторной работе.

В игре присутствуют:

- запуск по кнопке и повторная игра без перезагрузки страницы;
- движение змейки по клеточному полю 30 × 30;
- управление клавишами со стрелками;
- запрет обратного и двойного поворота за один игровой шаг;
- случайная генерация еды только в свободной клетке;
- рост змейки после поедания еды;
- текущий счёт и сохраняемый рекорд;
- столкновение со стенами и собственным телом;
- сообщение с причиной окончания игры.

### Устройство игрового поля

Поле реализовано с помощью Canvas размером 600 × 600 пикселей:

```html
<canvas id="game-canvas" width="600" height="600"></canvas>
```

Размер одной клетки равен 20 пикселям, поэтому по горизонтали и вертикали помещается по 30 клеток. Координаты змейки и еды хранятся не в пикселях, а в номерах клеток. При рисовании они умножаются на `cellSize`.

JavaScript получает Canvas и двумерный контекст через DOM:

```js
const canvas = document.getElementById("game-canvas");
const context = canvas.getContext("2d");
```

Перед каждым новым кадром поле очищается методом `clearRect()`, после чего змейка и еда рисуются заново методом `fillRect()`.

### Представление и движение змейки

Змейка хранится как массив объектов с координатами `x` и `y`. Первый элемент массива является головой:

```js
const snake = [
    { x: 10, y: 10 },
    { x: 9, y: 10 },
    { x: 8, y: 10 }
];
```

Для рисования частей используется обычный цикл `for`. При движении новая голова добавляется в начало массива методом `unshift()`, а хвост удаляется методом `pop()`. Если голова попала на еду, хвост не удаляется и длина змейки увеличивается.

### Игровой цикл

Функция `gameLoop()` выполняет один шаг игры:

1. очищает Canvas;
2. перемещает змейку;
3. проверяет столкновения;
4. рисует змейку и еду;
5. назначает следующий шаг.

Для повторного запуска используется `setTimeout()` с интервалом 300 миллисекунд:

```js
setTimeout(gameLoop, 300);
```

Следующий таймер создаётся только после завершения текущего шага. При столкновении функция завершается через `return`, новый вызов не назначается и игра останавливается.

### Управление

Нажатия стрелок обрабатываются событием `keydown`:

```js
document.addEventListener("keydown", changeDirection);
```

Направление хранится в переменных `directionX` и `directionY`. Условия не позволяют сразу развернуться в противоположную сторону. Флаг `directionChanged` разрешает только один поворот между соседними перемещениями змейки. Без этого ограничения быстрые нажатия двух клавиш могли развернуть голову в тело до следующего шага игры.

### Еда, рост и счёт

После поедания еды:

1. хвост не удаляется, поэтому змейка растёт;
2. текущий счёт `cnt` увеличивается;
3. новые координаты еды создаются с помощью `Math.random()` и `Math.floor()`;
4. цикл `for` проверяет, не занята ли клетка змейкой;
5. при необходимости координаты генерируются повторно.

Значение счёта выводится через свойство DOM-элемента `textContent`.

Лучший результат хранится в `localStorage`:

```js
let record = Number(localStorage.getItem("snakeRecord")) || 0;
```

Поэтому рекорд не сбрасывается после обновления или повторного открытия страницы. Текущий счёт при начале новой игры возвращается к нулю.

### Завершение и повторный запуск

Игра завершается в двух случаях:

- голова выходит за границы Canvas;
- координаты головы совпадают с координатами одной из частей тела.

Изначально для уведомления использовался `alert()`, но он блокировал страницу и требовал ручного закрытия. В итоговой версии причина проигрыша выводится обычным DOM-элементом в центре поля. Рядом остаётся кнопка «Начать игру».

При повторном запуске восстанавливаются начальные координаты змейки и еды, направление движения и нулевой счёт. Перезагрузка страницы не требуется, поэтому сохранённый рекорд остаётся доступным.

### Что использовано сверх основных примеров методички

Основная реализация опирается на рассмотренные темы: отдельный JS-файл, `defer`, DOM, функции, массивы, события, `setTimeout()` и Canvas.

Дополнительно использованы стандартные возможности браузера:

- `Math.random()` и `Math.floor()` — выбор случайной клетки для еды;
- `localStorage` — сохранение рекорда между запусками;
- атрибут `hidden` — показ и скрытие кнопки и сообщения;
- Flexbox и абсолютное позиционирование — размещение элементов интерфейса поверх Canvas.

Сторонние библиотеки и фреймворки не применялись.

### Важные нюансы к защите

- Canvas хранит размеры в пикселях, а игровые объекты — координаты клеток. Для рисования координата умножается на `cellSize`.
- `snake[0]` всегда является головой. При проверке столкновения с телом цикл начинается с индекса `1`, иначе голова всегда совпадала бы сама с собой.
- Массив `snake` объявлен через `const`, но его содержимое разрешено изменять методами `push()`, `unshift()` и `pop()`. Нельзя только присвоить переменной новый массив.
- Если еда съедена, `pop()` не вызывается, поэтому в массиве остаётся дополнительная часть и змейка растёт.
- Еда генерируется в цикле, пока не будет найдена клетка, не занятая змейкой.
- `setTimeout()` выполняет функцию один раз. Поэтому каждый `gameLoop()` самостоятельно назначает следующий вызов.
- После столкновения выполняется `return` раньше `setTimeout()`, поэтому игровой цикл прекращается.
- `directionChanged` защищает от двух быстрых поворотов за один шаг, а проверки направления запрещают разворот на 180 градусов.
- `localStorage` хранит строки, поэтому загруженный рекорд преобразуется функцией `Number()`.

- форма в [`adding_news.php`](./lab4/adding_news.php) передаёт новую запись через AJAX обработчику [`api/add_news.php`](./lab4/api/add_news.php), который сохраняет её в `news.json`.

### Как работает AJAX-загрузка новостей

После открытия главной страницы вызывается функция `loadNews()`. Она отправляет GET-запрос обработчику `api/get_news.php`. PHP возвращает содержимое `news.json`, после чего метод `response.json()` преобразует ответ в JavaScript-массив. Цикл `for...of` перебирает новости, создаёт элементы `tr` и `td` и добавляет их в `tbody` таблицы.

Если сессия отсутствует, обработчик возвращает HTTP-код `401`, а JavaScript переводит пользователя на страницу авторизации.

### Как работает AJAX-добавление новости

Сценарий отменяет обычную отправку формы методом `preventDefault()` и проверяет, что название, категория и дата заполнены. Затем значения преобразуются в JSON и передаются методом `POST` обработчику `api/add_news.php`. Обработчик проверяет сессию, читает существующие новости, добавляет новый элемент массива и записывает полный массив обратно в `news.json`. Полученное от PHP сообщение выводится на странице без её перезагрузки.

### Использование Bootstrap

Чтобы сохранить основное оформление сайта из лабораторной работы №2, Bootstrap 5.2 подключён на главной странице для обязательной по заданию таблицы. Таблица пользовательских новостей использует классы `table`, `table-bordered` и `table-striped`. Подключённый CSS Bootstrap также автоматически применяет свои базовые стили и типографику; отдельные правила для изменения шрифта не добавлялись.

Файл `users.json` первоначально содержит пустой JSON-массив:

```json
[]
```

При отправке формы JavaScript отменяет обычную перезагрузку страницы методом `preventDefault()`, проверяет заполнение полей и совпадение паролей. Затем логин и пароль преобразуются в JSON с помощью `JSON.stringify()` и передаются обработчику методом `POST`. PHP читает `users.json`, добавляет новый ассоциативный массив и сохраняет обновлённый список функциями `fopen()`, `fwrite()` и `fclose()`.

Для сохранения минимального объёма учебного кода пароль пока записывается в файл в исходном виде. В реальном приложении пароль необходимо хранить в виде хеша, однако хеширование отдельно не требуется заданием этой лабораторной работы.
